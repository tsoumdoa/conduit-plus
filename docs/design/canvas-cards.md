# Canvas cards — design, 2026-11-07

## Shape and sizing

Ship **Canvas Card**, one display component per card, under Display. Accept one Card and no outputs in PR1. Read the whole input tree and require exactly one valid CardSpec overall; do not let GH item iteration silently choose the last card. Empty input shows a placeholder; invalid/multiple input shows an error and clears stale content. Existing card producers remain unchanged.

Use custom GH_ComponentAttributes with a separate GH title/drag strip, input grip and measured card body. One Core logical pixel maps to one canvas unit. CardMeasure.Measure(spec, theme) determines body size; GH persists the component pivot, and size is recomputed after solving. Slot fields have no canvas meaning. No resize handle in PR1: width and visible rows come from the card. Later, a local resize override can persist width/visible rows with versioned serialization and one undo step per drag. Reject a board initially: GH already supplies spatial arrangement, grouping and navigation; a board adds a second layout system. Reject arbitrary bitmap stretching as resizing because it distorts text.

## Rendering and lifetime

Reuse RasterDrawing.Render → GdiCanvas → CardPainter, retaining only a System.Drawing.Bitmap in a GH-owned cache; do not create DisplayBitmap, OverlaySession or a Rhino conduit. Draw it in the attributes' Objects render channel, retaining GH wire/grip rendering and selection/warning/disabled chrome outside the card. Save/restore host Graphics state. The custom-attributes channel model is documented by [McNeel](https://developer.rhino3d.com/en/guides/grasshopper/custom-attributes/). Reject direct painter calls into GH Graphics for PR1: they repeat text/layout work on every pan and complicate graphics-state isolation.

Each display owns a CardStore. Project local view/brush state onto an immutable input snapshot before Update; incoming Rev is not authoritative. Cache key: stored Id/Rev, resolved Theme value, measured size and raster scale. Publish bitmap, spec and hit regions together; failed replacement keeps the previous complete frame. A theme change invalidates pixels even when CardStore reports no spec change. Expire layout only when measured size changes; painting never expires a solution.

Raster at effective canvas zoom × device DPI, derived from the actual render target transform without multiplying DPI twice. Pan reuses pixels. During continuous zoom, scale the existing bitmap; after 120 ms without scale changes, repaint visible cards at the settled scale for crisp text. Cull offscreen cards. A single UI-thread scheduler spreads settled-screen regeneration across frames (one card or roughly 8 ms per tick); no timer per component. Bound the document cache to 64 MiB and each bitmap to 16 MiB/4096 pixels per dimension, reducing raster scale uniformly when necessary. Evict least-recently-visible entries first. Large cards may consequently look soft; never allocate unchecked width × height × four bytes.

GH Preview off and component Hidden affect viewport preview, not this canvas body. Disabled/locked components retain their last successful image with explicit disabled chrome and no card interaction; with no image, show a placeholder. Pausing the solver retains the last result. Closing/unloading a document or deleting a component releases images, registrations and pending callbacks; document switching clears hover/capture.

Normal canvas screenshots include the card automatically. GH image export must render synchronously at the export target's effective scale, bypass screen culling/debounce and use disposable temporary bitmaps without replacing the screen cache. Export committed selection/sort/scroll, omit transient hover/tooltips. Validate the export render context against pinned GH 8.20 before implementation; current online API pages may describe Rhino 9. No claim of vector text in GH image export. ConduitPlusCapture/Pdf remain viewport commands.

## Interaction and selection

PR1 includes local table sorting, scrollbar track/thumb, keyed selection/Clear and hover details. Use RespondToMouseDown/Move/Up and key cancellation; transform canvas positions into card-local coordinates and reuse CardMeasure.Hits, TableSort and TableScroll. GH selection/drag remains on the outer strip, margins and non-actionable body; middle-button navigation and modified gestures pass through. Consume plain-left actions only on actionable regions. A row click commits on release over the same target within four screen pixels; exceeding that threshold cancels it. Scrollbar drag captures until release and cancels on Escape, lost capture, data/layout change or document switch. Never reinterpret an accepted card gesture as component dragging.

Keep the wheel for GH zoom in PR1; tables scroll through their scrollbar. Do not assume a RespondToMouseWheel override exists: the documented attributes API lists mouse down/move/up, not wheel. Later add Alt+wheel over a scrollable table through a verified canvas-level handler, consuming only handled gestures; do not reuse the Rhino global wheel hook. Reject plain wheel scrolling because it traps GH navigation. Use GH tooltip infrastructure for hovered hit details, refreshing the hit after scrolling/sorting and hiding it during navigation/drag; no Rhino tooltip texture or global overlay window.

Selection scope in PR1 is (GH document instance, Canvas Card InstanceGuid), backed by BrushState; scroll/sort additionally follow CardSpec.Id. Preserve state through data updates, clamp offsets, reset invalid sort columns and prune missing keys. Replacing the source Id resets local state. Selection is transient, without undo or .gh persistence. Hover, sort, scroll and selection only invalidate display; no selection outputs means no interaction solves.

**Do not implicitly share selection with Overlay in PR1**, even for the same CardSpec.Id or Link data. Current Overlay state belongs to (Rhino document, owner), and two owners intentionally differ. Card IDs identify producers; equal key strings or equivalent Link sets do not establish user intent. Later introduce an explicit shared selection-scope token, wired to Canvas Card and Overlay via appended optional inputs. A GH-document-scoped broker owns one BrushState per token, prunes against the union of registered card/Link keys, tracks hover origin and publishes snapshots to each host. Overlay alone supplies geometry highlighting; clear affects the explicit scope. Reject automatic per-source or per-Link-set sharing because it silently couples otherwise independent dashboards.

## Theme, scope and verification

New components default to **Auto** (Paper in Rhino light mode, Night in dark mode). Offer a persisted component-menu choice of Auto/Paper/Night/Smoke/Blueprint using shared Core presets and resolution policy; no duplicated palette or global Overlay setting. Saved explicit choices are retained; legacy reads without a theme stay Paper. Invalid saved choices fall back to Paper with a warning. Theme changes repaint/re-measure without solving and support undo. Auto is saved as a selection, and Rhino settings changes request a repaint without a solve. GH selection/disabled chrome remains recognizable around every theme.

PR1 covers six existing card kinds, measured layout, bounded raster caching/export, local interactions and theme choice. Defer boards, resize, wheel interception, cross-host linking and Selection/Events outputs. When outputs arrive, schedule one coalesced solve only after a committed selection change, never from Render/hover or snapshot projection; publishing/pruning must not emit fresh click events. Test feedback wiring explicitly to prevent solve loops.

Keep Core free of Rhino/GH types. Put coordinate conversion, cache-scale/budget decisions and local state reconciliation in pure Core helpers with tests for zoom/DPI transforms, revision/theme invalidation, sort/scroll clamping, stable keyed selection and source replacement. Keep Graphics, bitmaps, timers, attributes and document lifecycle in host code. Retain every existing GUID and input position; allocate one new stable component GUID, append future inputs only. Tests must not load RhinoCommon; follow the existing source-linked GDI test pattern for bitmap checks.

Before merging implementation: Debug build/full tests; live Rhino 8.20 checks for drag/select precedence, mixed DPI, disabled/hidden/preview states, undo/reload, image export and many visible cards. Verify GDI handles/memory plateau after repeated zoom, replacement and document close. Dispose every owned bitmap/Graphics/font/brush and unsubscribe handlers; GdiCanvas.Dispose does not own its supplied Graphics. Avoid flicker with atomic frame replacement and GH's existing painting cycle. Install from the integration checkout through the reviewing agent after implementation; this design-only change requires no installation.
