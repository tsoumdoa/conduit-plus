`tools/examples/Build-Examples.ps1`. The tool registers Rhino's built-in GH
objects and this checkout's `.gha` with an isolated ComponentServer, creates

reopens, solves, prints runtime messages, and checks the Overlay's owner session.

base-wire mode in place of the normal GH preview.

## PDF checks and fix

The normal hidden RhinoCore host successfully ran `ConduitPlusPdf.RunAutomated`.
Temporary document lines provide the vector viewport geometry; they are removed
after export. PyMuPDF independently reopened and rendered the **77,706-byte** PDF:

- **1 page**, **702.75 × 648.375 points**, exactly matching
  `1874 × 1729 / (96 × 2) × 72`.
- **9 / 9 card titles** extracted as searchable text, plus metrics and table data.
- Every title had a **9-point** font (12 CSS pixels × 72/96).
- All nine title origins matched the PNG layout converted to points:
  maximum coordinate error **0.0 points**.
- The rendered page was visually inspected for card placement, readable text,
  chart/table alignment and clipping.

**Fixed:** PdfCanvas treated FilePdf positions and stroke widths as points.
FilePdf actually takes these in **page dots** and converts them using the page
resolution; only font heights are in points. This double conversion compressed
the cards into the page's top-left and caused text to overlap. Positions/strokes
now use `dpi` dots per CSS pixel; fonts retain `72/96` points per CSS pixel.
The actual PDF title-coordinate assertions cover this regression. PNG capture
implementation is unchanged.

## Reproduce

```powershell
# Generate, reopen, solve and verify owner/session/card count; uses Debug by default.
./tools/examples/Build-Examples.ps1

$results = Join-Path $env:TEMP 'ConduitPlus'
./tools/examples/Build-Examples.ps1 -VerifyOnly -Exports -Output "$results/dashboard-verification"
foreach ($scale in 1, 2, 4) {
    ./tools/examples/Build-Examples.ps1 -VerifyOnly -Exports -Compact -Safe -Scale $scale -Output "$results/dashboard-compact-$scale"
}
foreach ($state in 'Drag', 'Tooltip', 'Selected') {
    ./tools/examples/Build-Examples.ps1 -VerifyOnly -Exports -Compact -Safe -State $state -Output "$results/dashboard-$($state.ToLowerInvariant())"
}

# Requires Pillow and PyMuPDF in Python; writes verification.json, PDF text and page PNG.
python tools/examples/Verify-Exports.py --full "$results/dashboard-verification" --compact-1 "$results/dashboard-compact-1" --compact-2 "$results/dashboard-compact-2" --compact-4 "$results/dashboard-compact-4" --drag "$results/dashboard-drag" --tooltip "$results/dashboard-tooltip" --selected "$results/dashboard-selected"

dotnet build ConduitPlus.sln -c Debug
dotnet test ConduitPlus.sln -c Debug
```

The final solution build passed with **0 warnings/errors**; **107 tests passed**.

## Limits and GUI follow-up

Full-dashboard **2×/4× are not verified**: at this large offscreen size, safe-mode
RhinoCore returned without invoking the conduit. The existing FrameCount guard
correctly refused to save a blank PNG. Normal-mode large capture attempts, and
repeated captures after the first frame in this host, also produced a native
`SEHException`. Fresh compact processes passed all three scales. These host
failures were not masked by resizing a PNG or replacing scene capture with a
synthetic composite. Safe-mode `FilePdf.Create` stalled; the normal hidden host
successfully supplied Rhino's PDF writer.

A human should open the `.gh`, change sliders, drag cards, sort/scroll the table,
hover/click model members, and run sequential full-scene 1×/2×/4× exports in the
Rhino GUI. Mixed-monitor DPI, physical mouse behavior and selection wires in the
PDF remain unverified. PDF extraction replaces the note's em dash with U+FFFD;
all card titles, numeric results and table text extract correctly. The vector
gradient uses the existing 128-band approximation. Keep PDF export experimental.
