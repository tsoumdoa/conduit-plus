Conduit+: web-rendered HUDs for the Rhino viewport

A rethink of Proving Ground's Conduit for Grasshopper. Charts, metrics and labels are written in HTML and drawn over the Rhino viewport. You place them by dragging them in the viewport, not by building rectangles in the XY plane, and they talk back to Grasshopper.

1 · The viewport

A working mock. Drag the viewport to orbit and the pinned labels follow the geometry. Hover a bar or a building to brush both ways. Move a slider to send a value back to Grasshopper and watch the cards re-solve. Turn on Edit layout and drag cards between slots.

2 · The Grasshopper canvas

Roughly the same result: a chart and a line of text in the view. The Conduit side is its minimal setup, since its Font, Palette and Style Sheet inputs are optional (adding them makes 14 components). Component counts end up close. The real differences are elsewhere. In Conduit the layout is geometry you build and keep rebuilding. In Conduit+ each card needs only its data plus one Overlay, layout is direct manipulation, and the Link component says which geometry each key refers to. That makes brushing and selection possible, which Conduit has no equivalent for.

Conduit+

0 components · 0 wires · incl. selection
The smallest working setup is two components: data → Bar → Overlay. Slot and theme come from the viewport and are stored on the Overlay. A wired Slot wins over a manual drag, which wins over automatic placement; wired properties show a lock in Edit layout.

3 · Component set

Each card needs its data and one Overlay; everything else has a default. Link binds keys to geometry so charts and the model can highlight each other. Optional inputs stay hidden until you zoom in on the component (ZUI), so the default face stays small. Precedence is always: wired input, then manual edit in the viewport, then automatic.
